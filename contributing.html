Contributing to ggnomics¶

Thanks for your interest in ggnomics. This document covers the development setup and the checks that run in CI.

Development environment¶

ggnomics targets Python 3.10–3.13. The vignettes additionally need a handful of analysis and data-access packages that are easiest to install through conda.

Testing and linting only (pip)¶

git clone https://github.com/MaximilianNuber/ggnomics
cd ggnomics

python -m venv .venv
source .venv/bin/activate

pip install -e ".[dev]"

The dev extra pulls in all, test, docs, and quarto, plus Ruff, pre-commit, tox, build, and twine.

Building the documentation (conda)¶

mamba env create -f environment-docs.yml
mamba run -n ggnomics-docs python -m pip install -e ".[docs,quarto]"

environment-docs.yml pins the vignette dependencies (scranpy, scrnaseq, pyexpressionatlas, experimenthub, pydeseq2, marsilea) that the worked examples execute against real public datasets.

Running the checks¶

Tests¶

pytest                                   # full suite
pytest tests/test_upset_plot.py -v       # one module
pytest --cov --cov-report=term-missing   # with coverage

MPLBACKEND=Agg is set by tests/conftest.py, so no display is needed.

tox¶

tox is the common entry point and mirrors what CI runs:

tox              # py, core, lint, format, build
tox -e py        # full pytest suite with coverage
tox -e core      # core-only install; proves the backends stay lazy
tox -e lint      # ruff check
tox -e format    # ruff format --check (read-only)
tox -e build     # python -m build + twine check
tox -e docs       # Sphinx site (the published one)
tox -e notebooks  # regenerate docs/tutorials/*.ipynb from the Quarto sources
tox -e quartosite # quartodoc build + quarto render
tox -e linkcheck  # internal-link validation of the rendered Quarto site

The documentation environments are deliberately excluded from the default envlist. notebooks and quartosite execute real analyses against public genomics datasets and need network access.

Ruff¶

ruff check .          # lint
ruff check . --fix    # lint and apply safe fixes
ruff format .         # format
ruff format --check . # verify formatting without writing

Configuration lives in [tool.ruff] in pyproject.toml. The line length is 120, matching the BiocSetup scaffold default. Optional[...] and List[...] are kept deliberately in public signatures (the UP006/UP007/UP035/UP045 rules are disabled) so that the annotations quartodoc renders match what Python 3.10 users see.

pre-commit¶

pip install pre-commit
pre-commit install       # install the git hook
pre-commit run --all-files

Generated documentation (vignettes/reference/, vignettes/_freeze/, vignettes/_site/) is excluded from the hooks, since reformatting it would create diffs that the next docs build immediately reverts.

Coverage¶

The full suite currently covers about 83% of ggnomics/. tox -e py enforces a floor of 80%, chosen to leave a little headroom without letting coverage silently erode. Raise the floor when coverage improves; please do not lower it to make a change pass.

Documentation¶

ggnomics publishes a Sphinx site in the BiocPy house style (furo theme, MyST Markdown, sphinx-apidoc), the same shape as scranpy. The workflow guides are included as executed Jupyter notebooks through nbsphinx.

The Quarto project in vignettes/ is retained: it is the authoring format for those guides, and it also builds its own site.

vignettes/*.qmd  --(tox -e notebooks)-->  docs/tutorials/*.ipynb  --.
                 --(tox -e quartosite)--> vignettes/_site/         |
                                                                   +--> tox -e docs
ggnomics/*.py    --(sphinx-apidoc, from docs/conf.py)--> docs/api/ --'   docs/_build/html/

Building the Sphinx site¶

pip install -e ".[docs]"
tox -e docs                 # or: sphinx-build -b html docs docs/_build/html

This never executes a notebook. docs/conf.py sets nbsphinx_execute = "never" because the committed notebooks already carry their outputs, so the build needs neither network access nor the analysis stack. That is what makes the ReadTheDocs build (see .readthedocs.yml) viable.

docs/api/ is generated by sphinx-apidoc, which docs/conf.py invokes on every build. It is gitignored — do not edit it by hand.

Regenerating the tutorial notebooks¶

The notebooks under docs/tutorials/ are produced from the Quarto sources:

mamba run -n ggnomics-docs python tools/build_tutorial_notebooks.py
# or one at a time
mamba run -n ggnomics-docs python tools/build_tutorial_notebooks.py upset

or tox -e notebooks. This runs quarto render <vignette>.qmd --to ipynb, which executes the guides against the real public datasets and embeds the resulting figures. Commit the regenerated notebooks together with whatever change prompted them.

Do not hand-edit docs/tutorials/*.ipynb — edit the .qmd source and regenerate.

Building the Quarto site¶

cd vignettes
mamba run -n ggnomics-docs quartodoc build
DOCS_PYTHON="$(mamba run -n ggnomics-docs python -c 'import sys; print(sys.executable)')"
QUARTO_PYTHON="$DOCS_PYTHON" quarto render

or tox -e quartosite. Quarto talks to the documentation environment’s interpreter through QUARTO_PYTHON; do not register a Jupyter kernel with jupyter kernelspec install.

quartodoc build reads the quartodoc: block in vignettes/_quarto.yml and writes vignettes/reference/*.qmd, vignettes/reference/_sidebar.yml, and vignettes/objects.json. Those are generated; regenerate rather than editing.

The freeze cache¶

vignettes/_freeze/ is committed on purpose, and _quarto.yml sets execute: freeze: auto. It is Quarto’s execution cache, and it is what keeps the HTML site and the tutorial notebooks consistent from a single execution. It also lets CI validate the Quarto site with quarto render --no-execute without re-fetching every dataset from Bioconductor and BiocPy services.

When you change a vignette’s code, the freeze entry for that page is refreshed automatically on the next render. To force a refresh, delete vignettes/_freeze/<page>/ and render again.

Checking links¶

python tools/check_internal_links.py vignettes/_site

or tox -e linkcheck. Walks the rendered Quarto HTML and verifies every internal link and fragment; external HTTP links are skipped so the check is deterministic and works offline. tox -e doclinks does the equivalent consistency pass for Sphinx.

Documentation environment¶

mamba env create -f environment-docs.yml
mamba run -n ggnomics-docs python -m pip install -e ".[docs,quarto]"

environment-docs.yml pins the vignette dependencies (scranpy, scrnaseq, pyexpressionatlas, experimenthub, pydeseq2, marsilea) that the worked examples execute against real public datasets.

A note on griffe¶

quartodoc 0.11 calls griffe’s numpy docstring parser with allow_section_blank_line, a keyword that exists only in griffe 1.x. With griffe 2.x installed, quartodoc build fails with:

TypeError: parse_numpy() got an unexpected keyword argument 'allow_section_blank_line'

The quarto extra therefore pins griffe>=1.5,<2. Remove the cap only once quartodoc supports griffe 2. This does not affect the Sphinx build, which does not use griffe.

Distributions¶

python -m build
python -m twine check dist/*

or tox -e build, which cleans dist/ first.

The optional-backend architecture¶

This is the part of the codebase most worth understanding before changing it.

Public plotting functions use functools.singledispatch, not an accessor class. plot_umap, plot_expression, and friends are generic functions whose pandas.DataFrame implementation carries the public docstring. Adapters for AnnData, SingleCellExperiment, SummarizedExperiment, and MuData live in ggnomics/_backends/ and register themselves onto those generics.

Optional containers must never be imported eagerly. The core install is numpy, pandas, and plotnine — nothing else. import ggnomics must succeed, and all DataFrame plotting plus ggnomics.upset must work, with none of anndata, mudata, singlecellexperiment, or summarizedexperiment installed.

ggnomics/_backends/__init__.py enforces this: it uses importlib.util.find_spec to check whether each optional package is importable, and imports the corresponding backend module only if it is. A backend that is installed but broken is allowed to raise, so a broken installation is not silently mistaken for an absent one.

When adding a backend or a new dispatch target:

  • put the container import inside the backend module, never at the top of a core module;

  • add the package to _BACKENDS in ggnomics/_backends/__init__.py;

  • add the extra to [project.optional-dependencies] in pyproject.toml — never to dependencies;

  • extend tests/test_backends.py, which asserts that each backend registers only when its package is present.

tests/test_backends.py and tests/test_public_api_contract.py are the guard rails for all of this. Both run on every pull request.

Design conventions¶

ggnomics follows the BiocPy developer guide:

  • public functions are snake_case and carry type hints;

  • plotting functions do not mutate the container they are given — tests/test_public_api_contract.py asserts this for DataFrame, AnnData, SingleCellExperiment, and SummarizedExperiment;

  • BiocPy containers are features × samples (or features × cells); extraction transposes into tidy one-row-per-observation frames;

  • SingleCellExperiment reduced dimensions are supported; a plain SummarizedExperiment has none, and embedding plots on one must raise an error that says so;

  • the legacy API (expression_violin, volcano_plot, heatmap_from_matrix, …) is retained for backwards compatibility and should not be removed without a deprecation cycle.

Pull requests¶

  1. Branch from main.

  2. Make the change and add tests.

  3. Run pre-commit run --all-files and tox.

  4. Add an entry to the Unreleased section of CHANGELOG.md.

  5. Open a pull request describing the change and why it is needed.
